# IdeaScan 研究质量优化实施记录

日期：2026-11-04。基线：`5c3463c`。本记录区分代码实现、本地验收和线上可用状态。

## 已实现

### 需求验证

- 原帖、父帖评论、竞品和历史研究材料进入统一证据池；证据 ID 稳定，支持与反证引用只能指向本次真实材料。
- 摘要保留评论、原文编号、冲突和付款自述；最终分析读取原文池，不再只依赖二次摘要。
- 模型失败、返回空对象或结构不完整时，保留原文并标记 `incomplete`；分数、情感和市场规模不补默认值。
- 数量多、高赞、推广、纯娱乐和竞品收费页不能单独让报告自动变成真实需求；无父帖身份的评论不作为独立来源计数。
- 情感比例仅根据有效评论 ID 的逐条分类计算，去重后采用最大余数法，保证非负且总和为 100。
- 保存采集全集，模型预算裁剪单独使用；断点和取消不会用裁剪后的 12 帖/24 评论覆盖全集。
- 主报告、完成预览、HTML/PDF 导出统一显示研究建议、证据不足和未完成；缺失趋势不绘制默认曲线，真实 0% 不被覆盖。
- 续跑使用原想法、标签、市场、平台和研究引用的范围指纹，拒绝变更范围后复用旧证据。旧报告缺少范围记录时明确拒绝，不静默新开付费采集。

### 优质需求发现

- 增加安心、情绪仪式、地域节日、兴趣关系、日常麻烦和工作效率六类入口，行业可选。
- 共享市场上下文与本地意图模板；实际查询记录可查看，TikTok 使用所选国家码，部分搜索不再固定中国区域。
- 同次模型调用先抽取带逐字原文的经历、任务、替代做法、代价和重复行为，再形成候选。
- 候选卡显示支持、反证、最大未知、最小软件切口、最小实验与研究建议；不把报价或购买自述当系统核验支付。
- 深入模式针对最多两个入围候选追加价格、替代和反证，最多六次网页查询，再复核一次；失败保留线索并降低建议状态，不无限重试。
- X/Threads 域名别名统一原帖身份，多信源分层进入有界证据池。

### 采集与研究交接

- 评论或后续页失败保留已经采得的原文，标记 `partial` 并向雷达、报告和未知项透传覆盖缺口。
- Threads 数字 API ID 与公开 shortcode 分开；转换海外样本时保留原帖链接与时间。
- 适配器统计只使用实际样本，不把帖子数乘 100，不生成固定周趋势。
- 新增私有研究档案，支持保存、恢复、三候选对比、继续补证和记录访谈/报价/试用/复用/购买反馈。
- 恢复档案后可复用旧原文定向补价格/替代/反证；研究范围变化时明确要求新建研究。
- 进入验证只传研究 ID 和候选 ID，服务端重新按账号查证材料；不在 URL 中携带密钥和整份原文。
- API 配置不写入研究档案，购买反馈保留 `self_reported` 来源，不冒充支付回调。
- 旧 Hunter 入口不再点击即自动发起验证。

## 数据库与发布

新增迁移：

1. `supabase/migrations/20261104090000_add_research_sessions.sql`：研究档案、账号 RLS 和更新时间排序索引。
2. `supabase/migrations/20261104091000_validation_run_writes.sql`：每轮运行标识、锁定验证记录的报告写入事务；仅 service role 可执行。

断点、取消和终态都使用同一事务入口，校验账号、`processing` 状态和运行标识。取消后旧任务、续跑前一轮和并发旧保存不能覆盖新结果。

**发布顺序：先应用并核对数据库迁移，再部署 `validate-idea-stream`、`cancel-validation`、`opportunity-discover`，最后发布前端。** 其他引用渠道共享代码的函数如需使用新适配器行为，也需重新部署。

本记录随优化代码一并交付。尚未对线上数据库执行迁移或部署前端与 Edge Functions。迁移未部署时，研究保存会明确失败；不会假装档案已经保存或带证据进入验证。Lovable 操作说明见 [更新说明](LOVABLE_RESEARCH_UPDATE.md)。

- 全量 Vitest：40 个测试文件、312 项通过，使用 `npx vitest run --maxWorkers=2`。
- 应用 TypeScript：`npx tsc --noEmit -p tsconfig.app.json` 通过。
- 三个目标函数 Deno 检查通过：`npx --yes deno check --no-lock --no-config ...`。
- `npm run build`、新增核心文件定向 ESLint、`git diff --check` 通过。
- 隔离 PGlite 执行真实新增迁移，24 项检查通过：账号隔离、跨账号写入拒绝、乐观并发、RPC 执行权限、旧运行拒写、取消后续跑、取消保留较新原文和报告不重复。
- 数据库复现脚本：`scripts/verify-research-db.mjs`。使用隔离安装的 `@electric-sql/pglite` 执行，不读取生产凭据或连接生产数据库。
- 浏览器验证未登录雷达：单一 H1、八平台、机会类型和语言入口正确；390px 视口无横向溢出，控制台无错误。
- 审查发现并修复：旧保存响应绑定新结果、模型空结构被误标完成、负情感比例、部分采集失败未透传、断点覆盖全集、取消和续跑的旧轮次回写。

## 仍需线上验证的边界

- 本地合同测试、PGlite 和构建不等于真实登录态、生产 RLS、供应商区域覆盖或真实需求验证。
- 本轮未调用 TikHub/OpenAI 等付费接口；需在部署后用有效配置执行少量、有预算的真实研究，检查查询相关性、引用和失败状态。
- 本地化目前是有限词表和意图模板，不是任意主题的通用翻译；界面展示实际查询，主题转换可能不完整时提示补充当地语言关键词。
- 历史研究材料仅校验账号归属，仍是研究材料，不代表已独立验证原文内容或地域。
- 手工购买反馈与真实支付回调分开；本轮未新增支付集成、用户招募或访谈执行。
- 旧热点/信号处理体系没有整体重构，旧报告保留“旧版研究判断”边界。全仓 ESLint 仍有历史问题，本轮只对新增核心范围清零。
