# 商机雷达首期

## 已实现的闭环

`/opportunity-radar` 使用现有登录和皮肤组件，输入国家、行业、关键词与平台，采集公开线索，再由模型提炼待验证候选。一键进入 `/validate` 时带入市场、平台和行业标签，不自动执行或扣减验证额度。

- 社媒复用六平台适配器与 `MultiChannelOrchestrator`；全网复用 Bocha、You.com、Tavily 的配置与供应商接口，但不使用旧搜索模块的中国市场过滤。
- 每个已配置搜索供应商只请求一次；社媒每个平台至多两页，保留至多十帖，对至多五帖抓取至多十条评论。快速模式使用更少样本。失败不切换关键词刷请求。
- 只接受可展示的 HTTPS 原文链接；不抓取证据链接的页面内容。相同 URL 的帖子与评论合并为一个来源，不把多个评论算作独立验证。
- 模型只可引用来源池中的 ID，每个候选至少两个不同原文来源。最多五个候选，证据不足则少返回或空结果，不生成演示商机。
- 紧迫度、痛点与竞品判断属于模型假设；采集到原文片段不等于结论已成立，国家查询也不等于来源作者位于当地。
- 结果仅留在本页内存，支持导出不含配置的 JSON。切换账号、取消和卸载时中止等待并屏蔽迟到响应；取消不能保证终止服务端调用或计费。

## 配置与部署边界

新函数目录：`supabase/functions/opportunity-discover`。本轮未执行部署、生产调用或真实密钥验收；上线时需要单独部署该函数。默认网关 JWT 检查未关闭，函数内部也始终调用 `auth.getUser(token)`，不沿用开发认证旁路。

默认只使用当前会话内存中的用户自带密钥，不写入设置表或报告表、不占用免费验证次数。管理员在配置网关全局预算后，可显式设置 `OPPORTUNITY_USE_SERVER_KEYS=true`，才允许复用现有服务端供应商池/环境变量作为缺失配置的回退。模型缺失、没有任何可用数据源时返回配置错误。

- 海外社媒沿用 `ENABLE_OVERSEAS_SOCIAL=true`；未开启则明确告知已跳过，不静默假装采集成功。
- 模型默认仅允许 `api.openai.com`、`api.deepseek.com`、`ai.gateway.lovable.dev` 的 HTTPS 地址。自定义公网模型代理必须由管理员明确加入 `OPPORTUNITY_LLM_ALLOWED_HOSTS`，逗号分隔精确域名，无通配符。
- 模型请求不跟随重定向，不跨端点重试；单次模型请求限时四十秒，全网单供应商限时二十秒。
- 供应商密钥不写日志、结果 JSON、浏览器持久化或新数据库记录。前端只发送本次请求所需的配置白名单。
- 统计使用实际返回数组和客户端请求计数，不使用适配器的估算总量或模拟周趋势。API 调用计数包含一次实际发出的模型分析请求，但不是金额估算。

## 不包含的能力

不修改表、迁移、RLS、RPC，不搭建第二套 Python/SQLite 服务。首期不提供跨会话机会库、后台队列、定时监控、提醒和付费转化归因。

G2、Capterra、Similarweb、WTO、Google Trends 没有在本轮自动接入，不能以研究平台名称宣称已有数据授权。

函数只提供实例内的每用户一分钟冷却、每实例最多两项并发。它不提供分布式配额、跨实例防刷或持久任务恢复；默认不启用公共付费密钥回退。在向大量用户开放服务端付费密钥之前，必须在网关补齐全局预算和速率限制。

## 人工验收

1. 部署函数后，使用自己的账号在设置页填入测试密钥，不在聊天中传递密钥。
2. 先只选全网，以具体国家、行业和工作流关键词执行一次；检查来源链接、片段、时间和候选不足提示。
3. 按平台逐个验证 TikHub；海外未灰度时应提示跳过，开启后检查真实响应与调用次数。
4. 点击候选进入验证，确认国家和行业进入想法正文、平台及标签正确预填，需要手动开始验证。仅全网候选会提示先补选社媒平台，不擅自替用户选择。
5. 检查取消、退出登录、切换账号与导出，确认旧结果不跨账号显示、导出不含任何配置。

本地 mock 测试不等于线上数据质量、付费意愿或供应商区域可用性的证明。
