

# 报告顶部重构：电梯演讲 + 用户画像融合

## 现状问题

当前 ScoreHeroCard（4列）+ PersonaCard（8列，内部又分 5:7）= 三块割裂的信息。用户看到的是：一个分数圆环、一个头像、一段重复出现两次的 description。信息密度低、叙事感弱。

## 设计理念

参考高级产品（如 Notion AI、Linear）的做法：**先讲故事，再给数据**。

```text
┌─────────────────────────────────────────────────────────────┐
│  电梯演讲区 (全宽)                                            │
│  ┌─────────┐                                                │
│  │ 85 分数  │  "为职场学习者打造的视频笔记工具"                   │
│  │ ○ 圆环   │   ──────────────────────────────               │
│  │ 真实刚需  │  overallVerdict 一段话总结                      │
│  └─────────┘  [开始构建 MVP]  [深度验证]                      │
├─────────────────────────────────────────────────────────────┤
│  目标用户画像 (全宽横向卡片)                                    │
│  ┌────────┐                                                 │
│  │ 头像    │  李明 · 互联网运营经理 · 28-35岁 · 月薪15-25k     │
│  │        │  "李明是一名忙碌的运营经理，工作之余需要..."          │
│  └────────┘                                                 │
│  ┌──────┐ ┌──────┐ ┌──────────┐ ┌──────────┐               │
│  │痛点×4 │ │诉求×4 │ │技术敏感65%│ │消费能力60%│               │
│  └──────┘ └──────┘ └──────────┘ └──────────┘               │
└─────────────────────────────────────────────────────────────┘
```

## 具体方案

### 1. 新建 ElevatorPitchHero 组件
合并 ScoreHeroCard 的评分逻辑 + 电梯演讲叙事：
- 左侧：紧凑的评分圆环（缩小到 120px）+ 评级标签（真实刚需）
- 右侧：`validation.idea` 作为大标题（产品一句话）、`aiAnalysis.overallVerdict` 作为副标题总结、行动按钮
- 全宽横向布局，比现在的竖向 ScoreHeroCard 更有叙事冲击力

### 2. 重构 PersonaCard 为横向紧凑布局
去掉现有的 12 列内部分割，改为：
- 头像 + 基本信息（名字/角色/年龄/收入）横向排列在一行
- description 作为用户故事独立一段
- 痛点 + 诉求 + 指标横向四栏排列在底部
- 去掉重复出现两次的 description（左侧卡片和右侧"用户故事"卡片）

### 3. Report.tsx 布局调整
- 原来的 `grid-cols-12`（4:8）改为两个全宽区块纵向排列
- QuickInsightsCards 保持不变，放在电梯演讲下方
- DataConfidenceCard 可嵌入电梯演讲区的右下角作为小标签

## 文件清单

| 文件 | 改动 |
|------|------|
| `ScoreHeroCard.tsx` | 重构为横向布局：左评分 + 右电梯演讲，接收 `idea` 和 `overallVerdict` props |
| `PersonaCard.tsx` | 重构为横向紧凑布局，去掉内部 12 列 grid，消除重复 description |
| `Report.tsx` | 去掉 4:8 grid，改为两个全宽 section 纵向排列 |

3 个文件，纯 UI 重构，不涉及数据逻辑变更。
